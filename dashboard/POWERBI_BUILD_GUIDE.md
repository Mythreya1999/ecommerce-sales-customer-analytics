# Power BI Build Guide

**The `.pbix` file itself has to be assembled in Power BI Desktop** — it is a binary container that
cannot be generated by a script. Everything it needs is in this folder and produces exactly the layout
in `screenshots/dashboard.png`.

Time to build: **20–30 minutes.** No modelling guesswork, no invented measures — all 40+ DAX measures
are written for you in `dax_measures.dax`.

---

| File | Purpose |
|---|---|

| `data/powerbi/fact_returns.csv` | order-level returns, for the returns page |

## Step 1 — Load the data (3 min)

1. **Get Data ▸ Text/CSV** → load all six files from `data/powerbi/`.
2. In **Power Query**, confirm these column types:

| Table | Column | Type |
|---|---|---|
| fact_sales | order_date | **Date** |
| fact_sales | date_key | Whole number |
| fact_sales | line_revenue, line_cost, line_profit, margin_pct | Decimal number |
| fact_sales | is_realised, is_returned, delayed_flag | Whole number |
| dim_date | date | **Date** |
| dim_date | date_key | Whole number |

3. **Close & Apply.**

## Step 2 — Build the star schema (4 min)

In **Model view**, create these relationships (all *one-to-many*, single direction):

| From (one) | → | To (many) |
|---|---|---|
| `dim_date[date_key]` | → | `fact_sales[date_key]` |
| `dim_customers[customer_id]` | → | `fact_sales[customer_id]` |
| `dim_products[product_id]` | → | `fact_sales[product_id]` |

Then:

- Right-click `dim_date` → **Mark as date table** → `date`.
- Sort `dim_date[month_name]` by `dim_date[month]` (otherwise months sort alphabetically).
- Sort `dim_date[month_year]` by `dim_date[month_year_sort]`.
- Hide from report view: every `*_id`, `date_key`, and all `is_*` flag columns.
- **Do not** relate `fact_returns` to `fact_sales` — it 1:* on `order_id` would fan out revenue.
  Keep it disconnected, or relate only to `dim_date`.

> ⚠️ **Never join `orders` and `order_items` as two fact tables in one visual.** That is a
> many-to-many and it will silently multiply your revenue. Use `fact_sales` only — it is already
> at order-item grain with the order attributes joined in.

## Step 3 — Add the measures (8 min)

Open `dax_measures.dax`, copy **one measure at a time** into **Modeling ▸ New Measure**, keeping the
display folder named in each block's comment. Set formats as you go:

| Measure | Format |
|---|---|
| Total Sales, Total Cost, Gross Profit, Lost Revenue, Order Book Value | Currency ₹, 0 decimals |
| Gross Margin %, Return Rate %, Delayed Delivery %, Sales YoY %, Repeat Rate % | Percentage, 1–2 decimals |
| Total Orders, Total Customers, Units Sold, Lost Orders | Whole number, thousands separator |
| Average Order Value, Revenue per Customer | Currency ₹, 0 decimals |

## Step 4 — Page 1: Executive Overview (8 min)

Canvas: **1600 × 1100**, background `#F4F6F9`.

**Row 1 — KPI cards** (Card visuals, 6 across):

| Card | Measure |
|---|---|
| Total Sales | `[Total Sales]` |
| Gross Profit | `[Gross Profit]` |
| Margin | `[Gross Margin %]` |
| Total Orders | `[Total Orders]` |
| Customers | `[Total Customers]` |
| Avg Order Value | `[Average Order Value]` |

Style: white card, `#2E5A88` left border 3px, label 10.5pt uppercase grey, value 24pt bold.

**Row 2 — Monthly revenue trend** (Line and clustered column chart, width 2/3)

- X-axis `dim_date[month_year]` · Column `[Total Sales]` · Line `[Gross Profit]`
- Secondary y-axis on.

**Row 2 — Customer segment** (Donut, width 1/3)

- Legend `dim_customers[customer_segment]` · Values `[Total Sales]` (segment by *sales*, not count).

**Row 3 — three bar visuals**

| Visual | Axis | Value |
|---|---|---|
| Sales by category | `dim_products[category]` | `[Total Sales]` |
| Profit by category | `dim_products[category]` | `[Gross Profit]` |
| Sales by region | `fact_sales[region]` | `[Total Sales]` |

**Row 4 — two visuals**

| Visual | Axis | Value |
|---|---|---|
| Top 10 products | `dim_products[product_name]` | `[Total Sales]`, filtered to `[Top 10 Products Flag] = 1` |
| Payment method | `fact_sales[payment_method]` | `[Total Sales]` |

**Row 4 — Sales vs profit** (Scatter)

- X `[Total Sales]`, Y `[Gross Profit]`, Details `dim_products[category]`, Size `[Units Sold]`.

## Step 5 — Slicers (3 min)

Place along the top, **Sync slicers** across pages:

| Slicer | Field | Style |
|---|---|---|
| Year | `dim_date[year]` | Dropdown |
| Month | `dim_date[month_name]` | Dropdown, multi-select |
| Category | `dim_products[category]` | Dropdown |
| Region | `fact_sales[region]` | Dropdown |
| Segment | `dim_customers[customer_segment]` | Dropdown |

**Card visual for the ₹ Cr display:** the `[Total Sales]` card defaults to `₹2,146,672,724`. If you
prefer `₹215 Cr`, either change the measure format to `#,##0.0,," Cr"` (two commas = millions —
divide again for crore as needed) or bind a card to `[Sales Cr Label]`.

## Step 6 — Page 2: Customer Analysis (optional, 5 min)

- Cards: `[Total Customers]`, `[Repeat Rate %]`, `[Revenue per Customer]`, `[Customers Active 90d]`
- Bar: `dim_customers[customer_segment]` × `[Total Sales]`
- Bar: `[RFM Segment]` × `[Total Sales]`
- Table: customer_id, segment, `[Customer Order Count]`, `[Total Sales]`, `[Recency Days]`,
  sorted by `[Total Sales]` desc, Top N = 20
- Matrix: `dim_date[month_year]` rows × `dim_customers[customer_segment]` columns, `[Total Sales]`

## Step 7 — Page 3: Product & Profitability (optional, 5 min)

- Matrix: category × `[Total Sales]`, `[Gross Profit]`, `[Gross Margin %]`, `[Return Rate %]`
- Bar: `[Product Cumulative Share %]` for the Pareto
- Bar: `fact_sales[discount_percentage]` × `[Gross Margin %]` ← **the money chart**
- Table: top 50 products with revenue, profit, margin, return rate

## Step 8 — Verify before you present

Sanity-check the model against these known-correct values:

| Check | Expected |
|---|---|
| `[Total Sales]` with no slicers | ₹2,146,672,725 |
| `[Gross Profit]` | ₹172,348,561 |
| `[Gross Margin %]` | 8.03% |
| `[Total Orders]` | 87,360 |
| `[Total Customers]` | 22,208 |
| `[Average Order Value]` | ₹24,573 |
| `[Lost Revenue]` | ₹261,358,234 |
| row count of fact_sales | 254,331 |

If `[Total Sales]` differs, the error is almost always one of:

1. Forgot `FactSales[is_realised] = 1` in a measure.
2. A relationship created `dim_products → fact_sales` as *many-to-many* instead of 1:*.
3. `fact_returns` joined into the sales model and fanning out rows.
4. Summed `final_amount` instead of `line_revenue` (that adds shipping and tax on top).

## Step 9 — Publish

**File ▸ Save as** → `dashboard/ecommerce_dashboard.pbix`, then **screenshot the page to
`screenshots/dashboard.png`** (`Windows + Shift + S`), or keep the rendered reference already there.
